# Screenshot capture checklist

No screenshots were present in the source repository during the V1 publication
review. These are capture instructions, not fabricated image placeholders. Do
not add broken image links to the root README before real captures exist.

Capture the actual local application at a consistent desktop viewport, preferably
1440 × 1000, with readable browser zoom and no credentials, terminal output,
personal bookmarks, local file paths or private project data visible.

- `01-executive-overview.png`: Sample mode showing project header, GREEN vs AMBER,
  leadership attention, ProgramPulse View and six dimensions.
- `02-status-conflict.png`: actual health comparison and executive implication;
  preserve enough context to identify the project and mode.
- `03-governance-challenges.png`: expand the no-release-impact challenge and show
  its supporting evidence references. Use synthetic evidence only.
- `04-upload-evidence.png`: Analyze Project Evidence with the four synthetic
  enterprise files selected, accepted types and explicit cost notice visible.
  Selection alone must not submit or incur provider usage.
- `05-live-assessment.png`: capture only after a real, successful, explicitly
  authorized Live run with synthetic files. Keep the LIVE label visible. This
  capture incurs provider cost; leave it absent until such a run is performed.

Never relabel Sample as Live, edit a screenshot to invent a result, or imply that
a mocked automated test is a live provider run. Review each PNG for sensitive
content before adding it to Git. Screenshots are optional portfolio assets;
missing captures do not prevent local application use.
